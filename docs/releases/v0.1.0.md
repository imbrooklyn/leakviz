# leakviz v0.1.0

`leakviz` v0.1.0 provides a deterministic, read-only CLI for inspecting Go
1.27 `goroutineleak` profiles and comparing snapshots.

## Install

Install from the v0.1.0 module tag with Go 1.27.x:

```bash
go install github.com/imbrooklyn/leakviz/cmd/leakviz@v0.1.0
leakviz --version
```

A source-checkout build reports `leakviz devel`. A module build from `@v0.1.0`
reports `leakviz v0.1.0`. The v0.1.0 distribution does not include project-built
binary or checksum files; it can also be built from source with
`go build ./cmd/leakviz`.

## Highlights

- Read Go 1.27 binary `goroutineleak` pprof snapshots from HTTP(S), files, or
  standard input.
- Classify channel, select, mutex, RWMutex, condition variable, and WaitGroup
  blocking evidence while retaining unknown stacks safely.
- Produce deterministic text or JSON schema v1 reports with exact and semantic
  fingerprints, counts, stacks, user frames, labels, and findings.
- Compare two snapshots by semantic identity while preserving all exact sites,
  with `NEW`, `INCREASED`, `DECREASED`, `RESOLVED`, and `UNCHANGED` statuses.

## Examples

```bash
leakviz localhost:6060
leakviz ./leak.pprof
cat ./leak.pprof | leakviz -
leakviz --json ./leak.pprof
leakviz --app github.com/acme/service ./leak.pprof
leakviz --timeout 2m localhost:6060
leakviz diff ./before.pprof ./after.pprof
leakviz diff --json ./before.pprof ./after.pprof
```

Flags must appear before operands. Diff flags appear after `diff` and before
the two sources.

## Runtime evidence and privacy

Entries in a Go 1.27 `goroutineleak` profile are goroutines that the runtime
determined cannot become unblocked. That evidence does not prove application
root cause, and garbage-collector reachability can hide real leaks. An empty
report is therefore not proof that no leak exists.

Profile labels may contain sensitive information. `leakviz` includes label
keys and values in reports by default, so protect reports before sharing them.
The tool does not upload profiles, start a server, or send telemetry.

## Compatibility and scope

v0.1 accepts gzip-compressed or uncompressed binary pprof snapshots with
exactly one `goroutineleak/count` sample type. It rejects ordinary goroutine
profiles, delta profiles, and unsymbolized positive-count samples. It does not
provide symbolization, root-cause proof, automatic fixes, watch or daemon
modes, a plugin DSL, a public Go library API, or fingerprint-version migration.

See the [README](../../README.md) for complete input rules, options, exit codes,
and v0.1 non-goals.

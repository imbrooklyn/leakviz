# leakviz v0.1.0

`leakviz` v0.1.0 提供确定性的只读 CLI，用于检查 Go 1.27
`goroutineleak` profile 并比较 snapshot。

## 安装

使用 Go 1.27.x 从 v0.1.0 module tag 安装：

```bash
go install github.com/imbrooklyn/leakviz/cmd/leakviz@v0.1.0
leakviz --version
```

Source checkout 构建会报告 `leakviz devel`。从 `@v0.1.0` 构建的 module binary
会报告 `leakviz v0.1.0`。v0.1.0 distribution 不包含项目构建的 binary 或 checksum
文件；也可以使用 `go build ./cmd/leakviz` 从 source 构建。

## 亮点

- 从 HTTP(S)、文件或标准输入读取 Go 1.27 二进制 `goroutineleak` pprof
  snapshot。
- 对 channel、select、mutex、RWMutex、condition variable 和 WaitGroup 阻塞证据
  进行分类，同时安全保留未知 stack。
- 生成确定性的文本或 JSON schema v1 报告，包含 exact 与 semantic fingerprint、
  count、stack、用户 frame、label 和 finding。
- 按 semantic identity 比较两个 snapshot，同时保留全部 exact site，并提供
  `NEW`、`INCREASED`、`DECREASED`、`RESOLVED` 和 `UNCHANGED` status。

## 示例

```bash
leakviz localhost:6060
leakviz ./leak.pprof
cat ./leak.pprof | leakviz -
leakviz --json ./leak.pprof
leakviz --app github.com/acme/service ./leak.pprof
leakviz --timeout 2m localhost:6060
leakviz diff ./before.pprof ./after.pprof
leakviz diff --json ./before.pprof ./after.pprof
```

Flag 必须位于 operand 之前。Diff flag 位于 `diff` 之后、两个 source 之前。

## Runtime 证据与隐私

Go 1.27 `goroutineleak` profile 中的记录是 runtime 已确定无法解除阻塞的
goroutine。该证据不能证明应用的 root cause，并且垃圾回收器的 reachability
可能隐藏真实 leak。因此，空报告不能证明不存在 leak。

Profile label 可能包含敏感信息。`leakviz` 默认在报告中包含 label key 和 value，
因此分享前请保护报告。本工具不会上传 profile、启动 server 或发送 telemetry。

## 兼容性与范围

v0.1 接受 gzip 压缩或未压缩的二进制 pprof snapshot，其中必须恰好包含一个
`goroutineleak/count` sample type。它拒绝普通 goroutine profile、delta profile
和具有正 count 但未 symbolized 的 sample。它不提供 symbolization、root-cause
proof、自动修复、watch 或 daemon 模式、plugin DSL、public Go library API 或跨
fingerprint version 迁移。

有关完整输入规则、选项、退出码和 v0.1 非目标，请参阅 [README](../README.zh-CN.md)。
